# 目录同步与公司共享空间 实现计划

> **面向实现者：** 按任务顺序做。每个任务先写失败测试，再写让该测试通过的最少代码，用该任务里的 `go test` 或前端测试命令确认。用 `- [ ]` 跟踪。完成一个任务并看到测试通过后再进入下一个。不要自行 git commit，除非执行者被明确要求提交。
>
> **规格：** [目录同步与公司共享空间](../规格文档/26-10-27%20目录同步与公司共享空间.md)
>
> **目标：** 企业部署从 ai-hub 员工目录同步账号，每人有个人空间，并自动以 editor 加入指定的公司共享空间；关闭公开注册后，企业登录不再新建账号。
>
> **架构：** 目录规则放在 `internal/directory`，只决定「绑定、新建、跳过、停用、加入公司空间」，不直接访问 HTTP。持久化放在 `internal/application/repository`。`user.LoginWithOIDC` 在系统设置 `auth.oidc_auto_provision=false` 时不再调用 `provisionOIDCUser`。公司空间 ID 存在已有系统设置注册表，指定时把该组织 `member_limit` 写成 0 并补加成员。未配置目录同步时，现有开源安装的 OIDC 首次登录行为不变。
>
> **技术栈：** Go、Gin、GORM、PostgreSQL 迁移 `versioned` 与 SQLite 迁移、Vue 3（`frontend/`，脚本 `tsx --test`）。
>
> **分层：** 接入层 `internal/handler` 只解析参数、鉴权并返回与现有系统管理接口相同的 JSON。领域规则在 `internal/directory`（绑定、新建、跳过、停用、公司空间成员）。数据访问在 `internal/application/repository`。领域层不写 HTTP 状态码，接入层不拼同步规则。
>
> **新建文件目录：**
> - 本仓库是 Go 服务，不是 `modules/<domain>/`。Go 单测继续放在被测包的 `*_test.go`，供 `go test` 使用。不把 Go 测试搬到 `__test__/`。
> - 不新开路由页面。继续改遗留页 `frontend/src/views/system/UserManagement.vue`。
> - 新的页内逻辑用 kebab-case：`frontend/src/views/system/directory-sync-state.ts`。
> - 新建前端单测只放 `frontend/src/__test__/views/system/directory-sync-state.test.ts`，镜像被测文件在 `src/` 下的位置。不在 `views/` 或 `components/` 旁新建 `*.test.ts`。已有的 `createUserDialogState.test.ts` 保持原位，本计划不迁移。
> - `tsx --test` 不解析 `tsconfig` 的 `@/`。这个新测试用相对路径导入被测文件。
>
> **接口形状：** 新接口挂在现有 `/api/v1/system/admin` 与 `/api/v1/me` 上，JSON 与 `ListAllUsersResponse` 一致：字段 snake_case，直接返回对象，使用已有的 `offset` / `limit` / `has_more`。不引入 `{ code, data, msg, message }` 信封，也不把用户列表改成 `page` / `pageSize`。
>
> **不改：**
> - `POST/GET/DELETE /mcp/:endpoint_id` 与 `mcp_` 令牌
> - [对外统一 MCP](../规格文档/26-10-24%20对外统一MCP按用户登录.md) 的实现；本计划只保证个人空间存在、公司空间成员角色为 editor
> - 知识库共享实现（`internal/application/service/kbshare.go`）。editor 成员沿用现有「来源租户 editor+ 才能共享」
> - 出站 MCP、IM、嵌入聊天
> - 系统管理员 `POST /system/admin/users/create` 的密码与审计
> - 用迁移强制所有安装变成 `invite_only`。企业部署用已有的 `DISABLE_REGISTRATION=true`
> - `frontend/package.json` 的 `test` 脚本
> - 遗留旁路单测文件的位置
