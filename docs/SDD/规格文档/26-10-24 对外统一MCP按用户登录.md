# 对外统一 MCP：使用者用自己的账号登录

**状态：** 已与需求方确认，待实现  
**确认日期：** 2026-10-24  
**分类：** 架构（新的对外身份模型；不改现有「按端点发令牌」通道的语义）  
**范围：** WeKnora 作为 MCP Server，给公司外部 Agent（Cursor、Claude、其他支持远程 MCP 的客户端）用。

## 1. 要达成的事

公司只公布 **一个** MCP 地址。员工在自己的 Agent 里填这个地址，第一次连接时用 **自己的 WeKnora 账号和密码**（若该部署已启用 OIDC，则走现有登录页上的同一种登录）完成授权。之后每次工具调用都算 **这个人** 的操作：能看见的知识库、能用的写操作、审计记录，都跟他在网页里登录后一样。Agent 的配置里不存放共享密钥，也不存放密码。

成功时：

- 运维文档里只有一个 URL，例如 `https://<内网主机>/mcp`。
- 员工 A 检索不到员工 B 无权阅读的知识库。
- 只有 Viewer 的人不能通过 MCP 上传或删除文档。
- 审计里的操作者是真实用户，不是 `mcp-<端点 id>` 这种合成账号。
- 已经发出去的「每个端点一把 `mcp_` 令牌」继续可用，语义不变：那把令牌代表端点，不代表人。

## 2. 现状（代码里已经如此）

现在对外的 MCP 不是「一个公司入口」，而是 **每个空间可以建多个端点**：

- 路径：`POST /mcp/:endpoint_id`
- 凭证：`Authorization: Bearer mcp_…`，令牌哈希存在该端点行上
- 身份：合成用户 `mcp-<端点 id>`，主体是 MCP 端点，角色按 Viewer，权限来自端点上的工具白名单和知识库范围（`MCPEndpointScope`）

`internal/types/mcp_endpoint.go` 写明：令牌认证的是端点，不是人。`internal/middleware/mcp_endpoint_auth.go` 按这个模型注入会话。

因此今天要给外部 Agent 用，就得有人进「设置 → 发布集成 → MCP Server」建端点、把一次性令牌贴进 Agent。令牌泄露等于该端点权限范围内的所有人共用一个身份；也无法按提问者做知识库 ACL。

另一条容易混淆的能力 **不在本规格里改**：

- 「工具箱 → MCP 服务」是 WeKnora **自己的 Agent 去调用别人的** MCP。那里的 OAuth 已经按调用者（principal）分开存 token。那是出站，不是本规格的入站。

## 3. 不做什么

- 不把用户名密码写进 MCP 的 JSON 配置，也不接受每次请求带密码。
- 不让一把共享 `mcp_` 令牌再额外带 `X-User` 去冒充别人。
- 不改出站 MCP 客户端、IM、嵌入聊天的授权。
- 不在本规格里接 dsh-work。dsh-work 若要连，连的就是这个同一 URL，登录的是 WeKnora 用户。
- 不取消现有 `/mcp/:endpoint_id`。机器对接、不需要「是哪个人」的集成继续用端点令牌。

## 4. 方案

### 4.1 采用：MCP 资源服务器 + 授权码（PKCE）

WeKnora 对这一个 URL 同时充当：

1. **资源服务器**：`/mcp` 上的 Streamable HTTP。
2. **授权服务器**：复用现有登录（用户名密码；部署已开 OIDC 时走现有 OIDC 登录），发出只用于这个 MCP 的 access token 和 refresh token。

外部 Agent 的标准行为是：请求 `/mcp` 没有用户令牌时得到 `401`，并带 `WWW-Authenticate`，指向受保护资源元数据；客户端打开系统浏览器走 **授权码 + PKCE（S256）**；用户在 WeKnora 登录页输入自己的账号密码并确认；客户端拿到 token 后再调工具。Cursor、Claude 等远程 MCP 客户端走的是这条，而不是「配置里写密码」。

动态客户端注册只接受：

- 回环地址（本机 Agent，如 `http://127.0.0.1:<端口>/callback`），以及
- 管理员预先写进白名单的重定向 URI。

不接受任意公网回调。

### 4.2 不采用

| 方案 | 原因 |
| --- | --- |
| 每人到网页复制一把个人令牌，再贴进 Agent | URL 可以是一个，但用户做的是复制密钥，不是在连接时登录。令牌长期放在 Agent 配置里，和现在贴 `mcp_` 同类。 |
| Agent 配置里写账号密码，或用 HTTP Basic | 密码进配置、进日志、进客户端存储。主流远程 MCP 客户端没有这个字段。 |

个人访问令牌可以在以后作为「不能开浏览器的 CI」补充，不在第一期。

## 5. 入口与发现

| 用途 | 路径 |
| --- | --- |
| 给人用的 MCP | `/mcp` |
| 受保护资源元数据 | `/.well-known/oauth-protected-resource` |
| 授权服务器元数据 | `/.well-known/oauth-authorization-server` |
| 授权页 / 换 token / 动态注册 | `/api/v1/oauth/mcp/authorize`、`/api/v1/oauth/mcp/token`、`/api/v1/oauth/mcp/register` |
| 现有机器端点 | `/mcp/:endpoint_id` 不变 |

`/mcp` 与 `/mcp/:endpoint_id` 的令牌不能混用。`mcp_` 令牌访问 `/mcp` 得到 401；用户 access token 访问某个端点 URL 得到 401。

未认证请求：

- 状态码 401
- 头：`WWW-Authenticate: Bearer realm="weknora-mcp", resource_metadata="<本机 origin>/.well-known/oauth-protected-resource"`
- 不在查询字符串里接受 token

元数据里的地址使用请求到达的对外 origin（与现有反代信任 `WEKNORA_TRUSTED_PROXIES` 一致），不写死 localhost。

## 6. 登录与令牌

1. 客户端带 PKCE `code_challenge`（仅 S256）打开授权页。
2. 未登录则进入现有登录。登录成功后的会话只用于这次授权，不把网页 JWT 直接交给 MCP 客户端。
3. 用户若属于多个空间，授权页必须 **选一个空间**。令牌只绑定这一个 `tenant_id`。要换空间就重新授权。第一期不做「一个 token 带多个空间、调用时再传 X-Tenant-ID」。
4. 用户确认授权的客户端名称和空间。
5. 授权码一次性、最多 10 分钟，绑定 client、redirect URI、PKCE、user、tenant。
6. 换发的 access token 有效期 1 小时，refresh token 有效期 30 天（滑动：每次成功刷新把 refresh 的过期时间延到从当时起 30 天，上限为首次签发后 90 天，超过必须重新登录）。
7. access token 的受众是这个 WeKnora 的 MCP 资源，不能拿去调用普通 `/api/v1`（网页和 API Key 仍走原登录）。这样 MCP 令牌泄露不能当全站 API Key 用。

用户在网页「已连接的应用」里可以撤销某一条授权。撤销后：

- 该 refresh token 立即作废；
- 已发出的 access token 在其剩余有效期内仍可用（最多 1 小时），不维护一份同步黑名单。第一期接受这个窗口。需要立刻切断时，管理员停用整个 `/mcp` 入口（见第 8 节）。

## 7. 调用时的身份与权限

一次工具调用的主体是：**该 access token 上的用户，在其绑定空间里的成员角色**。

生效权限 = 下面三者的交集：

1. **发布天花板**：该空间对 `/mcp` 开放的工具名列表；知识库天花板为空表示「不在这里再收窄」。
2. **成员角色**：与网页相同的 RBAC。Viewer 不能执行需要写入的工具；没有 `ingest` 类能力的角色不能上传。
3. **知识库 ACL**：与网页相同的自有、组织共享、经共享 Agent 可见。列表类工具只返回这个交集里的库，不返回「存在但无权」的库名。

越权调用返回工具错误，HTTP 仍可为 200（MCP 工具结果 `isError`），消息只说明当前用户无权，不说明目标是否存在。空间被停用、用户被停用、用户已离开该空间：401，客户端应丢掉 refresh 并重新登录。

`ask` 产生的会话归属这个用户，来源标记为 `mcp`。不能再写成 `mcp_endpoint:<tenant>:<endpoint>` 那种端点共用会话。续聊时，`session_id` 必须属于同一用户、同一空间、同一客户端授权；否则拒绝。

限流按 **用户 + 空间** 计数，默认每分钟 60 次工具调用，上限 6000，由第 8 节的配置决定。不按「全公司一个桶」计数，避免一个人打满其他人。

## 8. 谁来打开这一个入口

每个空间有一行配置（没有行 = 关闭）：

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `enabled` | 该空间是否允许从 `/mcp` 被选中并调用 | 关 |
| `tools` | 工具天花板 | 只读目录：列出知识库、检索、读文档 |
| `knowledge_base_ids` | 知识库天花板；空数组表示不再收窄 | 空 |
| `default_agent_id` | `ask` 未指定 Agent 时使用；空表示该空间内置快速问答 | 空 |
| `rate_limit_per_minute` | 该空间内每个用户 | 60 |

只有空间 Owner 或 Admin 能改。Contributor 和 Viewer 不能给自己打开入口。

`/mcp` 在授权完成前不知道空间。授权页只列出 **已启用** 且用户是活跃成员的空间。一个都没有时，授权页说明「管理员尚未开放统一 MCP」，不发码。

部署只有一个业务空间时，用户仍然只看到这一个可选空间，URL 不变。

## 9. 客户端配置

员工侧只需要：

```json
{
  "mcpServers": {
    "weknora": {
      "url": "https://kb.example.internal/mcp"
    }
  }
}
```

不写 `headers`，不写 API Key。客户端按 401 发现并打开浏览器。不支持 OAuth 发现的客户端不能使用 `/mcp`；它们若必须接入，继续使用某个 `/mcp/:endpoint_id` 和 `mcp_` 令牌，并接受那是端点身份而不是人。

## 10. 审计与保密

每条工具调用记：时间、用户 id、空间 id、客户端 id、工具名、是否允许、知识库 id（若有）。不记：密码、授权码、access token、refresh token、PKCE verifier。

动态注册下来的客户端记录名称和 redirect URI，供授权页展示和事后撤销。

## 11. 错误

| 情况 | 结果 |
| --- | --- |
| 无令牌或受众不对 | 401 + `WWW-Authenticate` |
| access token 过期 | 401；客户端用 refresh 换新的，失败则重新打开登录 |
| 该空间已关闭 `/mcp`，或用户已不是该空间成员 | 403，不执行工具 |
| 工具名不在天花板内 | JSON-RPC `-32602`，工具不执行（与现有端点白名单相同） |
| 用户无权访问该知识库 | 工具 `isError`，当不存在处理 |
| 超过该用户速率 | 429 |
| 管理员关闭 `enabled` | 新调用 403；已发出的 access token 同样拒绝（读配置，不依赖 token 黑名单） |

关闭 `enabled` 比「撤销某个用户」更严：立即生效，不等 access token 过期。

## 12. 测试

- 无 Authorization 访问 `/mcp`：401，且 `WWW-Authenticate` 含 `resource_metadata`。
- 授权码缺少 PKCE、或 challenge 方法不是 S256：拒绝。
- 授权码重放：第二次换 token 失败。
- 用户 A 的 token 看不到仅用户 B 有读权限的库；A 为 Viewer 时写入工具不执行。
- 天花板未包含某工具时，即使用户是 Owner 也不能从 `/mcp` 调用它。
- `ask` 的会话不能被另一个用户的 token 续上。
- 同一空间内用户 A 打满速率不影响用户 B。
- 将 `enabled` 设为 false 后，未过期的 access token 也被拒绝。
- 撤销授权后，refresh 失败；一小时内的 access token 仍可调用，直到过期或入口被关闭。
- 现有 `/mcp/:endpoint_id` 用 `mcp_` 令牌的用例保持通过；该令牌不能访问 `/mcp`。

## 13. 本规格里已经定下的选择

这些选择是为了能写清第一期，评审时可以改其中某一条，但不留空项：

1. 给人用的地址是固定的 `/mcp`，空间在登录授权时选择，不在 URL 里放用户 id 或空间 id。
2. 登录方式就是该部署现有的网页登录（密码和/或已启用的 OIDC），不新增第二套账号。
3. MCP access token 不能当普通 API 用。
4. 多空间用户一次授权只进一个空间。
5. 撤销单个客户端后，access token 最多再活 1 小时；立刻切断靠关闭该空间的 `/mcp`。
6. 第一期默认工具只有列出、检索、读文档。`ask` 和写入由管理员显式加进天花板。
7. 个人长期令牌（无浏览器）不做。

## 14. 实现时会碰到的现有代码

- 入站认证：`internal/middleware/mcp_endpoint_auth.go`（新入口不要复用「合成用户 `mcp-<id>`」这条分支）
- 端点模型：`internal/types/mcp_endpoint.go`（机器端点保留；空间级 `/mcp` 配置是另一张表或另一组字段，不把用户 OAuth 塞进 `mcp_` 令牌）
- 路由：`internal/router/router.go`、`internal/router/routes_mcp_endpoint.go`
- 工具执行与知识库 ACL：`internal/mcpserver` 现有工具处理器。人的入口应注入真实用户和成员角色，再走同一套 KB 访问判断。
