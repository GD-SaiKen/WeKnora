# 目录同步与公司共享空间

**状态：** 已与需求方确认，待实现  
**确认日期：** 2026-10-27  
**分类：** 账号来源与空间成员（不新做独立后台；不改 `/mcp/:endpoint_id` 的令牌语义）  
**范围：** 企业部署中，WeKnora 的账号从 ai-hub 员工目录进入，每人有个人空间，并自动加入一个指定的公司共享空间。

## 1. 要达成的事

员工不在 WeKnora 里自行注册。人从 ai-hub 的员工目录进来，用与 ai-hub 相同的企业登录进入 WeKnora。每个在用账号有自己的个人空间。系统管理员指定一个已有的共享空间作为公司空间后，这些个人空间自动以 editor 加入。个人知识库仍留在个人空间，由本人选定后再共享到公司空间。

成功时：

- 登录页没有注册入口。
- 目录里的在职员工能用企业登录进入，并看到自己的个人空间。
- 公司共享空间里能看到这些个人空间，角色是 editor。
- 只在个人空间、尚未共享的知识库，公司空间的其他成员看不到。
- 先用个人邮箱注册过的人，可以把该旧账号绑到自己的 ai-hub 身份上，空间和知识库留在旧账号。
- 系统管理员仍可应急开户。应急账号同样有个人空间，并加入公司共享空间。

## 2. 现状

WeKnora 已有系统管理员的「设置 → 系统设置 → 用户管理」（创建用户、启停、重置密码、升降系统管理员）。注册档位 `invite_only` 会关掉公开注册和凭邀请链接注册，已有账号仍可接受邀请。该档位不阻止 OIDC 首次登录建号，也不阻止系统管理员创建用户。

OIDC 登录按邮箱查找本地用户，找不到就按 `auth.default_tenant_mode` 新建。用户表没有 ai-hub 的 `user_id` 或 `subject`，也没有第二个邮箱。

个人空间是租户。共享空间（组织）的成员是租户，不是用户本人。把知识库共享进组织，要求来源租户在该组织中是 editor 或更高。组织默认有成员上限。

ai-hub 已提供服务身份可调用的 `GET /platform-api/v1/directory/users`（scope `platform.directory.read`），按游标分页，条目含 `user_id`、`subject`、显示名、邮箱、组织、状态、`tombstone`。dsh-work 已用这条接口做目录同步。本规格让 WeKnora 使用同一条接口，不另建用户源。

对外统一 MCP 见 [26-10-24 对外统一MCP按用户登录](./26-10-24%20对外统一MCP按用户登录.md)。本规格不实现该入口，只规定同步完成后授权页上会出现哪些空间。

## 3. 不做什么

- 不新建独立管理站，不把密码、MFA、会话从 authentik 搬进 WeKnora。
- 不按姓名自动合并两个账号。
- 不把个人知识库自动共享到公司空间或其他共享空间。
- 不自动加入公司空间以外的共享空间。
- 不取消系统管理员的「创建用户」。
- 不改出站 MCP、IM、嵌入聊天的授权。
- 不改 `/mcp/:endpoint_id` 与 `mcp_` 令牌。

## 4. 目录同步

WeKnora 用本应用在 ai-hub 登记的服务身份调用 `GET /platform-api/v1/directory/users`。启动后按固定间隔增量拉取，系统管理员可在用户管理里发起一次全量重拉。

每个人以 ai-hub 的 `user_id` 为稳定主键。同时保存 `subject`、显示名、邮箱、组织和状态。用户名取显示名，重名时加短后缀。目录用户不设置可登录的本地密码，密码登录直接拒绝。

邮箱一致（去掉首尾空白、忽略大小写）且该 WeKnora 账号尚未绑到别的 `user_id` 时，把 `user_id` 和 `subject` 写到这个已有账号上，不新建用户，也不再建一个个人空间。

对不上已有账号时，新建用户、新建他的个人空间，并按第 6 节加入公司共享空间。

同步不修改公司空间以外的成员关系，也不改已经写上的组织角色。自动加入时若已是成员，保留管理员后来调整过的角色。

## 5. 邮箱不一致时的绑定

自动绑定只发生在邮箱一致时。

邮箱不同的例子：旧账号是 `zhouheng@gmail.com` 且已有个人空间和知识库，目录邮箱是 `zhouheng@company.com`。同步按公司邮箱新建一个账号（含个人空间）。旧账号保持不变。

绑定由本人发起：先用旧账号登录，再走一次「绑定企业身份」。这次企业登录把 `subject` 和 `user_id` 写到**当前旧账号**上。公司邮箱记为该账号的别名。主邮箱仍是原来的注册邮箱。邀请、OIDC 查找同时认主邮箱和别名。一个邮箱只属于一个账号。由目录新建的账号不能密码登录；绑到已有密码的旧账号后，该密码登录仍然有效。

若公司邮箱上的那个新账号未被使用，绑定成功后把身份挪到旧账号，新账号停用，并将其个人空间移出公司共享空间。未被使用是指：个人空间里没有知识库，没有加入公司共享空间以外的共享空间，也没有别的用户成员。

若该新账号已被使用（有知识库，或有上述额外成员关系），绑定停住，不搬数据，由系统管理员处理。

系统管理员可以在用户管理里把一条尚未绑定的目录身份连到一个尚未绑定的本地账号，规则与本人绑定相同。一个 ai-hub 用户只对应一个 WeKnora 账号。

## 6. 个人空间与公司共享空间

目录同步新建的账号、系统管理员应急开户，都创建个人空间（`create_personal`）。已有账号继续使用他原来的个人空间。个人空间指该用户作为 Owner、随账号创建的那个租户。在用账号还没有个人空间时，补加前先建一个。

公司共享空间由系统管理员在系统设置里指定一个**已经存在**的共享空间。同步不创建这个空间。指定时把该空间的成员上限设为不限制。自动加入直接写入成员，不产生待审批；不改这个空间上邀请码加入是否要审批。

加入的是个人空间，角色为 editor。因此该成员可以把本人个人空间中的知识库共享进公司空间，也可以编辑那些按可编辑权限共享出来的内容，不能管理该空间的成员和设置。

加入发生在：

- 目录同步新建个人空间时
- 应急开户建好个人空间时
- 旧账号绑定成功后，用旧账号的个人空间加入
- 设置被指定时，以及之后的每次同步，把尚未加入的在用账号补进去

尚未指定公司共享空间时，同步仍建个人空间，只跳过加入。指定的空间已被删除时，同样跳过加入，不因此让整次同步失败。

## 7. 注册与应急开户

上线时把注册档位写成 `invite_only`。登录页不提供注册。`POST /auth/register` 与凭邀请链接注册返回 403。已有账号接受空间邀请保持可用。系统管理员仍可在系统设置里修改该档位；即使改回开放注册，企业登录也只进入已存在的账号，不因此新建用户。

企业登录只进入已经存在的账号（目录同步过的、绑定过 `subject` 的、或管理员创建的）。按 `subject` 查找，找不到再按主邮箱和别名查找。都找不到则登录失败，提示账号尚未开通，请联系管理员。不新建用户，不建个人空间。

「创建用户」只保留给系统管理员，写系统审计 `system.user_created`。这样开出的账号有一次性密码，可以密码登录，有个人空间，在已指定公司空间时以 editor 加入，来源标为管理员创建。之后目录里出现同一个邮箱时，按第 4 节绑到这个账号，不另建。

## 8. 停用

目录状态为停用或 `tombstone` 时：WeKnora 账号停用，吊销其登录会话，把他的个人空间从公司共享空间移出。个人空间和其他共享空间里的成员关系保留。重新变为在用后，账号恢复，个人空间再次以 editor 加入公司共享空间（若当时已是成员，则不覆盖现有角色）。

若该用户是最后一位仍启用的系统管理员，跳过停用，记入本次失败名单。

## 9. 同步失败与单人冲突

ai-hub 不可用或本次运行中断时，已同步的账号、个人空间和公司空间成员保持原样。运行标为失败并记下原因，不整批停用。

下列情况跳过这个人，继续其他人，并出现在失败名单中：

- 该 `user_id` 或 `subject` 已绑在另一个 WeKnora 账号上
- 同一 `user_id` 要改成的新邮箱已被别人使用（保留原邮箱）
- 停用会去掉最后一位系统管理员

用户管理页展示来源（目录、管理员创建、本地注册）、上次同步时间、成功人数、本次失败原因和失败名单。全量重拉只由系统管理员发起。

## 10. 与统一 MCP 的关系

员工对外仍使用一个 `/mcp`，登录与令牌规则以 [26-10-24 对外统一MCP按用户登录](./26-10-24%20对外统一MCP按用户登录.md) 为准。本规格只增加空间从哪来：

- 同步完成后，授权页至少列出他的个人空间（该空间的 `/mcp` 须已按那份规格启用，否则列表里不出现）。
- 个人空间已加入公司共享空间且该空间启用了 `/mcp` 时，列表再增加这一项。
- 一次授权只绑定他选中的一个空间。
- 未共享的个人知识库不会出现在公司空间的工具结果里。

## 11. 验收

- 注册档位为 `invite_only` 时，登录页无注册，两条注册接口返回 403。
- 目录中的新员工在一次成功同步后可以企业登录，名下有个人空间，且该个人空间是公司共享空间的 editor。其个人知识库未共享前，公司空间其他成员看不到。
- 该员工把一个库共享进公司空间后，其他 editor 按共享时给出的权限使用。
- 邮箱相同的旧账号在同步后仍是同一个用户，并带上 ai-hub 的 `user_id` 与 `subject`。
- 邮箱不同的旧账号，本人完成绑定后，企业登录和公司邮箱邀请都进入旧账号；未被使用的公司邮箱账号变为停用。
- 公司邮箱账号上已有知识库时，本人绑定停住，旧账号与新账号都还在。
- 未指定公司空间时，同步仍创建个人空间，且不加入任何共享空间。
- 目录停用某人后，该人企业登录失败，其个人空间不在公司共享空间成员中；他在其他共享空间的成员关系仍在。目录恢复后，他能再次登录，并回到公司共享空间。
- ai-hub 中断时，已有账号仍可企业登录，成员名单不变，用户管理页能看到失败原因。
- 系统管理员仍能创建用户；该用户能密码登录，并有个人空间。
- 企业登录一个目录中不存在、且未被绑定的新邮箱时，不产生新用户。

## 12. 本规格里已经定下的选择

1. 账号真相在 ai-hub，WeKnora 只保存映射、个人空间和空间成员。
2. 公司空间只有一个，由系统管理员指定已有共享空间，同步不创建。
3. 全员自动加入的角色是 editor；已是成员时不覆盖管理员后来改过的角色。
4. 知识库共享是本人的显式操作。
5. 停用只移出公司共享空间。
6. 应急开户保留，普通注册关闭，OIDC 不新建账号。
